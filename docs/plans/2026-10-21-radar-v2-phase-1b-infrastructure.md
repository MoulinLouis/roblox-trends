> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development for Part A (repository work). Part B (the server) is executed by the controller session itself over SSH, with the owner, never by subagents.

**Goal:** Run the phase 1a data core in production 24/7 on one server: PostgreSQL 18 + TimescaleDB, systemd timers, continuous backups to Cloudflare R2, Healthchecks monitoring, automatic deployment of the `radar-v2` branch, then import the v1 history and start collecting.

**Architecture:** Everything the server runs is versioned in the repository: systemd units in `ops/systemd`, PostgreSQL configuration and role SQL in `ops/postgresql`, shell entry points in `ops/bin`, and the two TypeScript operations commands (`provision:healthchecks`, `system-check`) in `scripts` with their logic in `src/lib/ops`. A provisioning script prepares a fresh Ubuntu 24.04 server; a pull-based deploy timer builds every green commit of the deploy branch into a release directory and switches a `current` symlink. Secrets never enter the repository or the conversation: the owner writes them into root-only files on the server.

**Tech Stack:** Hetzner Cloud CAX21 (arm64, 4 vCPU, 8 GB, 80 GB, Ubuntu 24.04.4), PostgreSQL 18 (PGDG), TimescaleDB 2.30.2 community (packagecloud), Node.js 24 (NodeSource), pgBackRest (PGDG) to Cloudflare R2, rclone, Tailscale (+ `tailscale serve`), ufw, systemd timers, Healthchecks.io (free plan, 20 checks), GitHub Actions CI (unchanged, plus shellcheck).

```sql
-- Run as a superuser by ops/bin/configure-database.sh; safe to run again. Both roles log in by peer authentication on
-- the local socket: the radar OS user owns the application, the analysis OS user maps to radar_analysis (pg_ident.conf).
DO $$
BEGIN
  IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'radar') THEN
    CREATE ROLE radar LOGIN;
  END IF;
  IF NOT EXISTS (SELECT FROM pg_roles WHERE rolname = 'radar_analysis') THEN
    CREATE ROLE radar_analysis LOGIN;
  END IF;
END
$$;
-- The system check reads pg_stat_archiver and the TimescaleDB job statistics.
GRANT pg_monitor TO radar;
-- Analysis sessions only read, and a forgotten query cannot hold the database.
ALTER ROLE radar_analysis SET default_transaction_read_only = on;
ALTER ROLE radar_analysis SET statement_timeout = '5min';
ALTER ROLE radar_analysis SET idle_in_transaction_session_timeout = '10min';
ALTER ROLE radar_analysis CONNECTION LIMIT 5;
```

```ts
import { HEALTHCHECKS_CONFIG, JOB_CONFIG } from "@/lib/config";
import { jobSlug, qualitySlug } from "@/lib/jobs/healthchecks";
import { JOB_NAMES } from "@/lib/jobs/types";

export const HEALTHCHECKS_API_URL = "https://healthchecks.io/api/v3/checks/";

// The fields of a Healthchecks check this repository manages; timeout (the expected period) and grace are in seconds.
export interface CheckSpec {
  slug: string;
  name: string;
  tags: string;
  desc: string;
  timeout: number;
  grace: number;
}

export function desiredChecks(): CheckSpec[] {
  const jobs = JOB_NAMES.flatMap((name): CheckSpec[] => {
    const { intervalMinutes, timeoutMs } = JOB_CONFIG[name];
    return [
      {
        slug: jobSlug(name),
        name: `${name} job`,
        tags: "radar job",
        desc: `Pinged by every ${name} run that completes, degraded or not; a failed run pings /fail.`,
        timeout: intervalMinutes * 60,
        grace: Math.ceil(timeoutMs / 1_000) + HEALTHCHECKS_CONFIG.heartbeatGraceMarginMinutes * 60,
      },
      {
        slug: qualitySlug(name),
        name: `${name} quality`,
        tags: "radar quality",
        desc: `Pinged only by fully successful ${name} runs, so a lasting degradation alerts.`,
        timeout: intervalMinutes * 60,
        grace: HEALTHCHECKS_CONFIG.qualityGraceMinutes * 60,
      },
    ];
  });
  const operations = Object.values(HEALTHCHECKS_CONFIG.operations).map(
    (check): CheckSpec => ({
      slug: check.slug,
      name: check.name,
      tags: "radar operations",
      desc: check.description,
      timeout: check.periodMinutes * 60,
      grace: check.graceMinutes * 60,
    }),
  );
  return [...jobs, ...operations];
}

// Creates the check, or updates the one with the same slug, and attaches every notification channel of the project.
export async function upsertCheck(
  apiKey: string,
  check: CheckSpec,
  fetchImpl: typeof fetch = fetch,
): Promise<{ slug: string; created: boolean }> {
  const response = await fetchImpl(HEALTHCHECKS_API_URL, {
    method: "POST",
    headers: { "Content-Type": "application/json", "X-Api-Key": apiKey },
    body: JSON.stringify({ ...check, channels: "*", unique: ["slug"] }),
    signal: AbortSignal.timeout(10_000),
  });
  if (response.status !== 200 && response.status !== 201) {
    const body = (await response.text()).slice(0, 500);
    throw new Error(`Healthchecks rejected ${check.slug}: HTTP ${response.status} ${body}`);
  }
  return { slug: check.slug, created: response.status === 201 };
}
```

```ts
import { sql } from "drizzle-orm";
import type { Database } from "./client";

export interface TimescaleJobHealth {
  jobId: number;
  procName: string;
  hypertableName: string | null;
  scheduleIntervalSeconds: number;
  scheduled: boolean;
  lastRunStatus: string | null;
  lastSuccessfulFinish: Date | null;
  initialStart: Date | null;
}

export interface ArchiverHealth {
  archiveMode: string;
  lastArchivedAt: Date | null;
  lastFailedAt: Date | null;

// TimescaleDB starts last_successful_finish at -infinity, which would parse to an invalid date and never look late.
function toDate(value: Date | string | null): Date | null {
  if (value === null) return null;
  const date = new Date(value);
  return Number.isFinite(date.getTime()) ? date : null;
}

// The policies added by the migrations (ids from 1000; lower ids are TimescaleDB's own jobs).
export async function readTimescaleJobs(db: Database): Promise<TimescaleJobHealth[]> {
  const result = await db.execute<{
    job_id: number;
    proc_name: string;
    hypertable_name: string | null;
    schedule_seconds: number;
    scheduled: boolean;
    last_run_status: string | null;
    last_successful_finish: Date | string | null;
    initial_start: Date | string | null;
  }>(sql`
    select j.job_id, j.proc_name, j.hypertable_name, extract(epoch from j.schedule_interval)::int as schedule_seconds,
      j.scheduled, s.last_run_status, nullif(s.last_successful_finish, '-infinity') as last_successful_finish, j.initial_start
    from timescaledb_information.jobs j
    left join timescaledb_information.job_stats s on s.job_id = j.job_id
    where j.job_id >= 1000
    order by j.job_id
  `);
  return result.rows.map((row) => ({
    jobId: row.job_id,
    procName: row.proc_name,
    hypertableName: row.hypertable_name,
    scheduleIntervalSeconds: row.schedule_seconds,
    scheduled: row.scheduled,
    lastRunStatus: row.last_run_status,
    lastSuccessfulFinish: toDate(row.last_successful_finish),
    initialStart: toDate(row.initial_start),
  }));
}

export async function readArchiver(db: Database): Promise<ArchiverHealth> {
  const result = await db.execute<{
    archive_mode: string;
    last_archived_time: Date | string | null;
    last_failed_time: Date | string | null;
  }>(sql`select current_setting('archive_mode') as archive_mode, last_archived_time, last_failed_time from pg_stat_archiver`);
  const row = result.rows[0];
  return {
    archiveMode: row?.archive_mode ?? "off",
    lastArchivedAt: toDate(row?.last_archived_time ?? null),
    lastFailedAt: toDate(row?.last_failed_time ?? null),
  };
```

**Step 4: Implement the evaluation**

`src/lib/ops/system-check.ts`:

```ts
import type { ArchiverHealth, TimescaleJobHealth } from "@/db/system-health";
import { SYSTEM_CHECK_CONFIG } from "@/lib/config";

export interface SystemHealthInput {
  now: Date;
  diskUsedShare: number;
  archiver: ArchiverHealth;
  jobs: readonly TimescaleJobHealth[];
}

export interface SystemHealthResult {
  ok: boolean;
  problems: string[];
  summary: string;
}

const percent = (share: number) => `${Math.round(share * 1_000) / 10}%`;
const minutesBetween = (from: Date, to: Date) => Math.floor((to.getTime() - from.getTime()) / 60_000);

export function evaluateSystemHealth(input: SystemHealthInput, config = SYSTEM_CHECK_CONFIG): SystemHealthResult {
  const problems: string[] = [];
  if (input.diskUsedShare > config.maximumDiskUsedShare) {
    problems.push(`Disk ${percent(input.diskUsedShare)} used (limit ${percent(config.maximumDiskUsedShare)})`);
  }
  problems.push(...archiverProblems(input.now, input.archiver, config));
  for (const job of input.jobs) {
    const problem = jobProblem(input.now, job, config);
    if (problem) problems.push(problem);
  }
  const archived = input.archiver.lastArchivedAt ? `${minutesBetween(input.archiver.lastArchivedAt, input.now)} min ago` : "never";
  const summary = problems.length
    ? problems.join("\n")
    : `OK: disk ${percent(input.diskUsedShare)}, last WAL archived ${archived}, ${input.jobs.length} TimescaleDB policies on time`;
  return { ok: problems.length === 0, problems, summary };
}

function archiverProblems(now: Date, archiver: ArchiverHealth, config: typeof SYSTEM_CHECK_CONFIG): string[] {
  if (archiver.archiveMode !== "on") return ["WAL archiving is off: point-in-time recovery is not possible"];
  if (archiver.lastFailedAt && (!archiver.lastArchivedAt || archiver.lastFailedAt > archiver.lastArchivedAt)) {
    return [`WAL archiving has failed since ${archiver.lastFailedAt.toISOString()}`];
  }
  if (!archiver.lastArchivedAt) return ["No WAL segment archived yet"];
  const age = minutesBetween(archiver.lastArchivedAt, now);
  return age > config.maximumArchiveAgeMinutes ? [`No WAL segment archived for ${age} min`] : [];
}

// A policy that never succeeded is measured from its initial start, so a fresh database is not reported as late.
function jobProblem(now: Date, job: TimescaleJobHealth, config: typeof SYSTEM_CHECK_CONFIG): string | null {
  const label = `${job.procName}${job.hypertableName ? ` on ${job.hypertableName}` : ""} (job ${job.jobId})`;
  if (!job.scheduled) return `${label} is paused`;
  const reference = job.lastSuccessfulFinish ?? job.initialStart;
  if (!reference) return null;
  const allowed = Math.max((job.scheduleIntervalSeconds / 60) * config.lateJobIntervals, config.minimumLateJobMinutes);
  const late = minutesBetween(reference, now);
  return late > allowed ? `${label} has not succeeded for ${late} min (last run ${job.lastRunStatus ?? "none"})` : null;
}
```

```ts
const units = new URL("../../../ops/systemd/", import.meta.url);

// The settings of a unit file, by key (sections are ignored: no key here appears in two sections).
function readUnit(path: string): Map<string, string[]> {
  const settings = new Map<string, string[]>();
  for (const line of readFileSync(new URL(path, units), "utf8").split("\n")) {
    const match = /^([A-Za-z]+)=(.*)$/.exec(line.trim());
    if (match) settings.set(match[1], [...(settings.get(match[1]) ?? []), match[2]]);
  }
  return settings;
}

function onlySetting(unit: Map<string, string[]>, key: string): string | undefined {
  const values = unit.get(key) ?? [];
  expect(values.length, key).toBeLessThanOrEqual(1);
  return values[0];
}

// "*:M/S:SS" repeats every S minutes from minute M; "*:MM:SS" runs once an hour.
function startTimes(onCalendar: string): { step: number; offsetSeconds: number; minutes: number[] } {
  const repeated = /^\*:(\d+)\/(\d+):(\d{2})$/.exec(onCalendar);
  const hourly = /^\*:(\d{2}):(\d{2})$/.exec(onCalendar);
  if (repeated) {
    const [first, step, second] = repeated.slice(1).map(Number);
    const minutes = Array.from({ length: 60 / step }, (_, index) => first + index * step);
    return { step, offsetSeconds: first * 60 + second, minutes };
  }
  if (hourly) {
    const [minute, second] = hourly.slice(1).map(Number);
    return { step: 60, offsetSeconds: minute * 60 + second, minutes: [minute] };
  }
  throw new Error(`Unsupported OnCalendar: ${onCalendar}`);
}
```

**Step 2: Write the scripts**

Conventions for every script that pings Healthchecks (they follow from the plan review):
- The ping URL holds the project's ping key, so it reaches curl through `--config -` on standard input, never the command line (`/proc/*/cmdline` is readable by every local user).
- No `set -E`: an ERR trap inherited by command substitutions would fire inside `$(…)` even when the outer command is a tested condition. Instead an ERR trap only records where the script stopped, and an EXIT trap sends the `/fail` ping for any non-zero exit that `fail` did not already report.
- A command substitution that may legitimately fail ends in `|| true` (or sits in a condition).

```bash
#!/usr/bin/env bash
# Deploys the newest commit of the deploy branch once its CI run passed: builds it next to the live release, pauses
# the job timers only when the commit brings migrations, then switches the live release. Run every 5 minutes by
# radar-deploy.timer, and by hand for the first deployment. Exits 0 when there is nothing to deploy.
set -euo pipefail

readonly repository=MoulinLouis/roblox-trends
readonly branch="${RADAR_DEPLOY_BRANCH:-radar-v2}"
readonly root=/opt/radar
readonly mirror="${root}/repo.git"
readonly releases="${root}/releases"
readonly current="${root}/current"
readonly keep_releases=3
# A release younger than this may still run a 30-minute job or the legacy import: it is never pruned.
readonly minimum_release_age_minutes=120
readonly job_timers=(radar-census.timer radar-poll.timer radar-votes.timer radar-charts.timer radar-explore.timer radar-thumbnails.timer)
readonly job_wait_seconds=300
readonly migration_attempts=5

log() { printf '%s %s\n' "$(date -u +%Y-%m-%dT%H:%M:%SZ)" "$*"; }

# The ping URL holds the project's ping key: it reaches curl on standard input, never on the command line.
ping() {
  [[ -n "${HEALTHCHECKS_PING_BASE:-}" ]] || return 0
  printf 'url = "%s"\n' "${HEALTHCHECKS_PING_BASE%/}/radar-deploy${1}?create=1" \
    | curl --config - --silent --show-error --max-time 10 --retry 3 --data-raw "${2:-}" >/dev/null \
    || log "Healthchecks ping failed"
}

# Job timers that are enabled must run whenever no deploy is in its critical section. Pausing collection on purpose
# means disabling them (docs/operations.md), which this never undoes.
start_job_timers() {
  local timer timers=()
  for timer in "${job_timers[@]}"; do
    if systemctl is-enabled --quiet "${timer}" 2>/dev/null; then timers+=("${timer}"); fi
  done
  if ((${#timers[@]} > 0)); then systemctl start "${timers[@]}" || log "Could not start ${timers[*]}"; fi
}

reported=false
failed_at="an unexpected step"
trap 'failed_at="line ${LINENO}: ${BASH_COMMAND}"' ERR
finish() {
  local status=$?
  if ((status != 0)) && [[ "${reported}" == false ]]; then ping /fail "deploy.sh stopped at ${failed_at} (exit ${status})"; fi
  start_job_timers
}
fail() {
  reported=true
  log "Deploy failed: $1"
  ping /fail "$1"
  exit 1
}
as_radar() { runuser -u radar -- "$@"; }

[[ "$(id -u)" == 0 ]] || { echo "deploy.sh must run as root" >&2; exit 1; }
# One deploy at a time: a manual run and the timer's must not build the same release.
exec 9>/run/radar-deploy.lock
flock --nonblock 9 || { log "Another deploy is running"; exit 0; }
trap finish EXIT
set -a
# shellcheck source=/dev/null
. /etc/radar/radar.env
set +a

if [[ ! -d "${mirror}" ]]; then
  as_radar git clone --quiet --mirror "https://github.com/${repository}.git" "${mirror}" || fail "Could not clone ${repository}"
fi
# GitHub can be briefly unreachable: the next run retries, and nothing is deployed meanwhile.
if ! as_radar git -C "${mirror}" fetch --quiet --prune origin; then
  log "git fetch failed; retrying on the next run"
  ping "" "git fetch failed; nothing deployed"
  exit 0
fi
target="$(as_radar git -C "${mirror}" rev-parse --verify "refs/heads/${branch}^{commit}")"
live_path="$(readlink -e "${current}" || true)"
live="${live_path:+$(basename "${live_path}")}"
# .deployed is written last, so a deploy that stopped after the switch is completed by the next run.
if [[ "${target}" == "${live}" && -f "${current}/.deployed" ]]; then
  ping "" "Up to date at ${live}"
  exit 0
fi
if [[ -f "${releases}/${target}.failed" ]]; then
  fail "The build of ${target} failed earlier (${releases}/${target}.failed); push a fix"
fi

# Only a commit whose CI job "validate" passed is deployed.
if ! checks="$(curl --fail --silent --show-error --max-time 20 --header 'Accept: application/vnd.github+json' \
  "https://api.github.com/repos/${repository}/commits/${target}/check-runs?check_name=validate")"; then
  log "GitHub API unreachable; retrying on the next run"
  ping "" "GitHub API unreachable; nothing deployed"
  exit 0
fi
ci="$(jq -r '[(.check_runs // [])[] | select(.name == "validate")] | sort_by(.started_at) | last
  | "\(.status // "missing") \(.conclusion // "none")"' <<<"${checks}" 2>/dev/null || echo "unreadable none")"
read -r ci_status ci_conclusion <<<"${ci}"
if [[ "${ci_status}" != completed || "${ci_conclusion}" != success ]]; then
  log "CI for ${target} is ${ci_status}/${ci_conclusion}; not deploying"
  ping "" "CI for ${target} is ${ci_status}/${ci_conclusion}; live release ${live:-none}"
  exit 0
fi

# Build outside the live release, at low priority so the jobs keep their pace. A failed build is not retried until a
# new commit arrives.
release="${releases}/${target}"
if [[ ! -f "${release}/.built" ]]; then
  log "Building ${target}"
  rm -rf "${release}" "${release}.tar"
  install -d -o radar -g radar "${release}"
  as_radar git -C "${mirror}" archive --output="${release}.tar" "${target}" || fail "Could not export ${target}"
  as_radar tar -xf "${release}.tar" -C "${release}" || fail "Could not extract ${target}"
  rm -f "${release}.tar"
  build_log="${releases}/${target}.log"
  if ! as_radar env -C "${release}" nice -n 10 npm ci --no-audit --no-fund >"${build_log}" 2>&1 \
    || ! as_radar env -C "${release}" nice -n 10 npm run build >>"${build_log}" 2>&1; then
    mv -f "${build_log}" "${releases}/${target}.failed"
    rm -rf "${release}"
    fail "Build of ${target} failed: $(tail -c 2000 "${releases}/${target}.failed")"
  fi
  rm -f "${build_log}"
  as_radar touch "${release}/.built"
fi

# Job timers pause only when the release brings migrations, so a schema change never races a job's statements.
if [[ -z "${live}" ]] || ! as_radar git -C "${mirror}" diff --quiet "${live}" "${target}" -- drizzle; then
  for timer in "${job_timers[@]}"; do systemctl stop "${timer}" 2>/dev/null || true; done
  # Running jobs keep their own release (never pruned while young); waiting lets the migration take its locks.
  waited=0
  # Captured, not piped into grep -q: an early grep exit would SIGPIPE systemctl and, under pipefail, end the wait.
  while [[ -n "$(systemctl list-units --no-legend --state=activating,active 'radar-job@*.service')" ]]; do
    if ((waited >= job_wait_seconds)); then
      log "Jobs still running after ${job_wait_seconds} s; migrating anyway (lock_timeout protects them)"
      break
    fi
    sleep 5
    waited=$((waited + 5))
  done
fi

migrated=false
for attempt in $(seq 1 "${migration_attempts}"); do
  if as_radar env -C "${release}" npm run --silent db:migrate; then
    migrated=true
    break
  fi
  log "Migration attempt ${attempt} of ${target} failed"
  sleep 30
done
[[ "${migrated}" == true ]] || fail "Migrations of ${target} failed; ${live:-no release} stays live"

ln -sfn "${release}" "${current}.next"
mv -T "${current}.next" "${current}"
cp -r "${release}/ops/systemd/." /etc/systemd/system/
systemctl daemon-reload
ln -sfn "${current}/ops/bin/radar.sh" /usr/local/bin/radar
```

```bash
#!/usr/bin/env bash
# Weekly proof that the backups restore: restores the latest backup into a scratch directory, starts it on a private
# socket with archiving off (it must never push WAL into the repository), compares it with production and reports to
# the radar-restore-test check. It starts failing for lack of room around 55% disk use, before the system check's 70%.
set -euo pipefail
readonly target=/var/lib/postgresql/radar-restore-test
readonly sockets=/run/radar-restore-test
readonly port=5499
readonly bin=/usr/lib/postgresql/18/bin
# Production keeps writing during the test (up to max_wal_size of WAL) and the scratch cluster writes its own.
readonly margin_kb=$((8 * 1024 * 1024))

# The ping URL holds the project's ping key: it reaches curl on standard input, never on the command line.
ping() {
  [[ -n "${HEALTHCHECKS_PING_BASE:-}" ]] || return 0
  printf 'url = "%s"\n' "${HEALTHCHECKS_PING_BASE%/}/radar-restore-test${1}?create=1" \
    | curl --config - --silent --show-error --max-time 10 --retry 3 --data-raw "${2:-}" >/dev/null || true
}
restored() { runuser -u postgres -- psql -X -At -h "${sockets}" -p "${port}" -d radar -c "$1"; }
production() { runuser -u postgres -- psql -X -At -d radar -c "$1"; }
cleanup() {
  if [[ -f "${target}/postmaster.pid" ]]; then
    runuser -u postgres -- "${bin}/pg_ctl" -D "${target}" -m immediate stop >/dev/null 2>&1 || true
  fi
  rm -rf "${target}" "${sockets}"
}

log="$(mktemp)"
reported=false
failed_at="an unexpected step"
trap 'failed_at="line ${LINENO}: ${BASH_COMMAND}"' ERR
finish() {
  local status=$?
  if ((status != 0)) && [[ "${reported}" == false ]]; then ping /fail "restore-test.sh stopped at ${failed_at} (exit ${status})"; fi
  cleanup
  rm -f "${log}"
}
trap finish EXIT
fail() {
  reported=true
  echo "Restore test failed: $1" >&2
  ping /fail "$1"
  exit 1
}

[[ "$(id -u)" == 0 ]] || { echo "restore-test.sh must run as root" >&2; exit 1; }
ping /start
cleanup

# Measured by PostgreSQL rather than du, which fails when a file vanishes during the walk.
data_kb="$(production 'select (sum(pg_database_size(oid)) / 1024)::bigint from pg_database')"
free_kb="$(df --output=avail -k /var/lib/postgresql | tail -n 1 | tr -d ' ')"
((free_kb > data_kb + margin_kb)) || fail "Not enough free disk: ${free_kb} kB free for ${data_kb} kB of data and ${margin_kb} kB of margin"

install -d -o postgres -g postgres -m 700 "${target}" "${sockets}"
# Synchronous archive-get: production's asynchronous archive-push owns the spool and its lock.
runuser -u postgres -- pgbackrest --stanza=radar --pg1-path="${target}" --archive-async=n --type=immediate \
  --target-action=promote --archive-mode=off restore >"${log}" 2>&1 \
  || fail "pgbackrest restore failed: $(tail -c 2000 "${log}")"
# Debian keeps the configuration outside the data directory: the scratch cluster gets empty files and its settings on
# the command line. hot_standby is off because archive recovery refuses settings below the primary's, and
# timescaledb-tune raised max_worker_processes; the test needs connections only once the cluster is promoted.
runuser -u postgres -- sh -c ": >'${target}/postgresql.conf'; echo 'local all postgres peer' >'${target}/pg_hba.conf'; : >'${target}/pg_ident.conf'"
runuser -u postgres -- "${bin}/pg_ctl" -D "${target}" -w -t 1800 -l "${target}/restore-test.log" \
  -o "-p ${port} -c listen_addresses= -c unix_socket_directories=${sockets} -c hot_standby=off -c shared_preload_libraries=timescaledb -c timescaledb.telemetry_level=off -c archive_mode=off" \
  start >/dev/null || fail "The restored cluster did not start: $(tail -c 2000 "${target}/restore-test.log")"
for _ in $(seq 1 360); do
  if [[ "$(restored 'select pg_is_in_recovery()' 2>/dev/null || true)" == f ]]; then break; fi
  sleep 5
done
[[ "$(restored 'select pg_is_in_recovery()' 2>/dev/null || true)" == f ]] || fail "The restored cluster did not finish recovery in 30 min"

restored_games="$(restored 'select count(*) from games')"
production_games="$(production 'select count(*) from games')"
((restored_games * 100 >= production_games * 95)) || fail "Restored ${restored_games} games, production has ${production_games}"
production_runs="$(production 'select count(*) from job_runs')"
age="$(restored 'select coalesce(extract(epoch from now() - max(started_at))::bigint, -1) from job_runs')"
if ((production_runs > 0)) && ((age < 0 || age > 2 * 86400)); then
  fail "The newest restored job run is ${age} s old"
fi
version="$(restored "select extversion from pg_extension where extname = 'timescaledb'")"
ping "" "Restored ${restored_games}/${production_games} games, newest job run ${age} s old, TimescaleDB ${version}"
```

## Execution notes

(Record decisions and surprises here as tasks complete; committed code is authoritative over the code blocks above.)

- Plan review (before execution), folded into the tasks above:
  - The restore test starts the scratch cluster with `hot_standby=off`, because archive recovery refuses settings below the primary's and `timescaledb-tune` raises `max_worker_processes`. It uses a synchronous `archive-get` (`--archive-async=n`), measures the data size with `pg_database_size`, and keeps an 8 GB margin.
  - `legacy.env` quotes the URL (its `&` broke shell sourcing) and keeps the password in `PGPASSWORD`. The Aiven role also reads the identity sequences, which `pg_dump -t` includes, and gets its password with `\password`.
  - The v1 dump is read back in full and checksummed before it is uploaded.
  - The system check maps TimescaleDB's `-infinity` `last_successful_finish` to `null`, so a policy that never succeeded is measured from its initial start.
  - Scripts:
    - Healthchecks URLs reach curl on stdin.
    - No `set -E`; an ERR trap records the failing line, and an EXIT trap pings `/fail` for any unreported non-zero exit.
    - `deploy.sh` takes a `flock`, marks a release `.deployed` last, blocks a failed build until a new commit arrives, pauses the job timers only when `drizzle/` changed, probes the dashboard after a restart, never prunes releases younger than 2 h, and restarts enabled job timers on every exit (pausing collection therefore means disabling the timers).
  - PostgreSQL minor upgrades are manual (PGDG is not an unattended origin), and the reboot time is 04:48.
  - Rollback starts by stopping the deploy timer; `configure-backups.sh --config-only` is the first step of a rebuild.
  - The import pauses the TimescaleDB policies, the deploy timer and the system check.
  - CI runs `shellcheck --severity=warning`.
